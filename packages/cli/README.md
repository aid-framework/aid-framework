# CLI

The command-line interface that drives the whole loop: scaffold, generate, run, ingest, evaluate, trace, and
eject.

**Responsibility**

- Implement the commands in [`docs/design.md` §11](../../docs/design.md): `init`, `gen`, `dev`, `ingest`,
  `eval`, `trace`, `cost`, `guard`, `migrate`, `eject`, `doctor`.
- Orchestrate `spec → IR → generator plugins`, and surface validation and capability errors with actionable
  file/line context.
- Provide `--dry-run` (via the generator SDK's pure `plan()` phase) and `--force`, plus `--json` on every
  command and CI-friendly exit codes.

The CLI owns **no** AI behavior of its own; it is a thin driver over [`../spec/`](../spec/),
[`../ir/`](../ir/), and [`../generators/`](../generators/).

> **Naming:** the command is **`aid`** — `aid init`, `aid gen`, `aid eval`, and so on. The command surface is
> specified in [`docs/design.md` §11](../../docs/design.md); the framework name and architecture are in
> [`§5`](../../docs/design.md).

## Status: the Phase 0 commands and `ingest` are implemented

| Command | Behaviour |
| --- | --- |
| `aid init [dir] [--from <spec>] [--target <name>] [--force] [--gen]` | Scaffolds `app.spec.yaml` — a starter, or `--from <spec>` imported once it lowers to an IR and passes the gates — plus a `README.md`. **Does not generate**: `aid gen` does, and `--gen` is only the convenience for the file-set a person types next. An existing spec is never replaced without `--force`; an existing `README.md` is never replaced at all. |
| `aid validate [spec]` | Parses, schema-validates, builds the IR, and runs **every** build-time gate. Diagnostics carry `file:line:column`. |
| `aid gen [spec] [--target <name>] [--dry-run] [--force]` | Runs `plan()` always, and writes unless `--dry-run`. Reports `created`/`updated`/`unchanged`/`kept`/`conflicts`. A generator-owned file that has been hand-edited is refused: the regenerated bytes land beside it as `<file>.aid-rej` and the command exits non-zero. `--force` takes those bytes instead. |
| `aid ingest [spec] [--target <name>] [--retriever <id> \| --all] [--dry-run]` | Runs the generated ingest module for a declared retriever through the Python toolchain, and propagates its exit code. `--retriever` names one; `--all` runs every retriever the spec declares; passing both, or neither, is a usage error. `--dry-run` is forwarded to that module, which applies the chunker and reports the counts a run would write without opening a store, so the CLI does not keep a second answer to the same question. A retriever id the spec does not declare is a usage error naming the ids that do exist. `--all` over a project with no retrievers succeeds with nothing to do. A declared retriever whose module has not been generated exits non-zero and says to run `aid gen`. Ingest is idempotent because a chunk id is a content hash and the store upserts on it, so a second run over unchanged documents replaces rather than appends. |
| `aid eval [spec] [--target <name>] [--suite <id>] [--baseline]` | Runs the project's generated eval module through the Python toolchain, streams its report, and propagates its exit code. `--baseline` records a fresh baseline from an N-run sample instead of gating against one. |

Every command answers `--json` with one JSON document on stdout and `-h`/`--help` with its usage. Exit codes
are `0` (the project is as asked), `1` (the spec, a gate, the target, or the working tree said no), and `2`
(the invocation was wrong or the CLI failed internally).

`dev`, `trace`, `cost`, `guard`, `migrate`, `eject`, and `doctor` are specified in
[`docs/design.md` §11](../../docs/design.md) but are **not** implemented; they are deferred past Phase 0.

**The CLI is glue, and only glue.** Spec parsing and validation come from [`../spec/`](../spec/), the IR
builder and every build-time gate from [`../ir/`](../ir/), and the generation plan, the manifest, and the
drift algorithm from [`../generator-sdk/`](../generator-sdk/) and the target plugin. A gate reimplemented
here would be a second source of truth for the same rule, so there are none. Determinism is the generator
SDK's contract and the CLI adds no liberty to it: `aid gen` on an unmodified project is a no-op that writes
no bytes, and a file under the target's business directory is created once and then never written again.

Reference: [`docs/design.md` §11](../../docs/design.md).
