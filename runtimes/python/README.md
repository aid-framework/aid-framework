# AID runtime — Python

The Python runtime library: the behavior layer imported by apps generated by the
[`py-fastapi`](../../packages/generators/py-fastapi/) generator. Generated code is thin glue; this is where
the behavior lives ([`docs/design.md` §4](../../docs/design.md), principle 1).

Distribution name **`aid-runtime-python`**, import package **`aid_runtime`**. The two differ deliberately: a
distribution name is conventionally hyphenated, and a Python import package cannot be. That asymmetry is
asserted in `tests/test_package.py` so it cannot drift.

Requires Python 3.11+.

```sh
pip install -e ".[dev]"   # the runtime plus its test/lint/type tooling
pytest -q
```

## What it provides

| Module | Provides |
| --- | --- |
| `gateway.py` | `ModelGateway` — alias resolution, capability negotiation, ordered fallback, cost accounting, GenAI spans |
| `providers/` | The `Provider` protocol, one HTTP adapter (`OpenAICompatibleProvider`), and one deterministic fake (`FakeProvider`) |
| `prompts.py` | `PromptTemplate` / `PromptRegistry` — versioned prompts, typed rendering, few-shot assembly |
| `structured.py` | `build_agent` — structured output via Pydantic AI only |
| `tools.py` | `Tool` / `ToolExecutor` — declared definitions, argument validation, structured results |
| `pipeline.py` | `Pipeline` / `PipelineContext` — plain-async named steps over a frozen context |
| `evals/` | Datasets, metrics, and the statistical baseline gate |
| `tracing.py` | OTel GenAI spans: `llm_span`, `record_usage`, `record_cost`, `record_exception` |
| `cost.py` | `Budget`, `CostLedger`, `estimate_cost_usd` |
| `types.py` | The request/response/usage/spec models everything else is typed against |

98 names are exported from `aid_runtime`. The layering is acyclic and one-directional: `errors` and `types` import
nothing else in the package, `gateway` is imported only by the package `__init__` and the eval runner, and no
core module imports a higher layer back.

## Model pinning

An **alias resolves to an exact provider model id**, including a pinned version. That is not cosmetic: a
baseline recorded against `gpt-4o` means nothing if the alias floats to `gpt-4o-2026-…` on the next run, so an
**unknown alias is an error** (`UnknownModelAliasError`) rather than a silent fall-through to a provider
default.

```python
from aid_runtime import (
    Budget,
    CompletionRequest,
    CostProfile,
    ModelGateway,
    ModelSpec,
    OpenAICompatibleProvider,
    PinnedModel,
)

spec = ModelSpec(
    name="gpt-4o-2024-08-06",
    provider="openai-compatible",
    cost=CostProfile(input_per_1k_usd=0.0025, output_per_1k_usd=0.01),
    context_window=128_000,
    max_output_tokens=4096,
)

gateway = ModelGateway(
    providers={"openai-compatible": OpenAICompatibleProvider(api_key=...)},
    aliases={"small": PinnedModel(alias="small", spec=spec)},
    budget=Budget(max_usd=5.0, scope="nightly"),
)

result = await gateway.generate("small", CompletionRequest.prompt("hello"))
result.text, result.usage, result.cost_usd, result.alias, result.attempts, result.fell_back
```

- `resolve(alias)` returns the `PinnedModel` (alias + `spec`); `provider_for(alias)` its provider. `require(alias,
  capabilities)` asserts the capabilities *and* returns the pinned model, checking **both** sides — a model that
  supports tool calling behind an adapter that does not serialise tool definitions cannot tool-call — and raises
  `CapabilityMismatchError` naming what is missing.
- `generate(alias, request, *, fallbacks=(), budget=None)` tries the alias then each fallback **in the order
  given**, and reports the aliases actually attempted on the result. Fallbacks are ordered, not conditional.
- Every charged call opens a span and updates the ledger. `CostLedger` tracks per-call `LedgerEntry` records
  and yields a `SpendSummary`; `Budget` (`max_usd`, `max_total_tokens`, `scope`) is enforced before the call,
  and `estimate_usage` / `estimate_cost_usd` price a request from a model's `CostProfile` when a caller wants
  to check before spending.

## The eval harness gates on statistics, not equality

Phase 0 ratifies sampling-based gating: a model is **expected** to vary between runs, so a metric that
compares two runs for equality is either always red or measuring nothing. Non-determinism here is not a bug to
be fixed; it is the property the gate has to be robust against.

- `Dataset` — versioned cases with inputs, expectations, tags and metadata; `from_records` / `from_json` /
  `from_path`, `to_json`, and lookups by id (`case`) and by tag (`by_tag`).
- Metrics — `ExactMatch`, `NormalizedContains`, `JsonSchemaValid`, and `LlmJudge`. `metric_names` and
  `default_metrics` cover the common set.
- `run_evaluation(dataset, runner, metrics, runs=5)` samples the runner **N times** and produces an `EvalRun`
  of per-run metric means, so a single unlucky run does not decide the verdict. `evaluate_once` is the
  single-pass primitive; a `DatasetRun` gives per-case outcomes and a rendered `summary()`.
- `EvalBaseline.from_run(run, model=..., note=...)` stores a baseline as JSON: per metric the sample count,
  mean and spread. `runtimes/python/tests/fixtures/capitals-baseline.json` is a committed example.
- `BaselineGate(thresholds).evaluate(run, baseline)` compares the current sample against the baseline using a
  one-sided normal test, with each `Threshold` carrying `metric`, an optional absolute `min_mean`, a
  `max_regression` allowance, and an `alpha` significance level. A metric passes by clearing `min_mean`, by
  being within `max_regression` of the baseline, or by regressing only within sampling noise.

Two deliberate limits:

- **`LlmJudge` is implemented and never CI-required.** A judge is itself a model call, and a gate that
  depends on one non-deterministic call inside the gate you are trying to trust is the problem this design
  avoids. `gateway_judge(gateway, alias)` builds the judge call when a caller wants it.
- **`GateConfigurationError` refuses a threshold on a model-derived metric**, because an N-run sample of a
  probabilistic judge cannot carry a fixed threshold honestly.

`cost` is the enforced budget; a latency p95 budget belongs with Phase 2 dashboards, not here.

## Control flow is plain async

`Pipeline` is a list of named async (or plain) steps over a `PipelineContext` that is **frozen**, so a step
cannot mutate what an earlier step observed — it returns a new context, which keeps a failed run's state
inspectable. A step may return a context, a mapping, or `None`. Each step runs in its own span, a step raising
anything aborts the run with the original exception chained (`PipelineError.__cause__`), and `StopPipeline` is
the supported early exit.

**Pydantic AI is used for structured output and nothing else** (`structured.build_agent`). The orchestration
library stays out of the control-flow path deliberately, so it remains swappable, and **no graph/orchestration
dependency is taken at all**: agent loops, escalation routing and orchestration frameworks are deferred to
Phase 2 ([`docs/design.md` §14](../../docs/design.md)).

Tracing follows the OTel GenAI semantic conventions: `gen_ai.*` attributes for the operation, model, provider,
request parameters and usage, with AID-specific values namespaced `aid.*` so the two never collide. A failing
call records its exception exactly once.

## Development

Four gates, all run by the `python` job in [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) over
real content:

```sh
pytest
ruff check .
ruff format --check .
mypy
```

`mypy` runs strict over `src` **and** `tests`, so the tests are type-checked too. The `python` job is a real
gate but is **advisory**: the `main` ruleset requires the `node`, `workflows` and `licenses` contexts only.

`tests/fixtures/capitals-baseline.json` is regenerated from `FakeProvider(accuracy=0.6, seed=0)` over 10 runs
— the fake is seeded and deterministic per call, so the committed baseline reproduces exactly while a fresh
sample of it still varies, which is exactly the property the gate has to tolerate.

**Non-responsibility:** no app-specific prompts, tools, or rubrics. Those belong to the generated app's
`business/` tier ([`docs/design.md` §8.4](../../docs/design.md), the seam).

**Status:** Phase 0 scope implemented. One thing declared but not implemented, on purpose: `ModelGateway.stream`
and the `streaming` capability name a request/response-only transport and raise `FeatureDeferredError` rather
than pretending. Also deferred (§14): escalation routing, retrieval, memory, guardrails, prompt/semantic
caching, rate limiting, token buckets, and adapters beyond the one HTTP provider and the fake.

Reference: [`docs/design.md` §9, §12, §14, §17 #2](../../docs/design.md).
